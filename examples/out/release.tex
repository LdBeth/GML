\gmlstart{h2}{id=cap,anchor=cap,text=Capacity planning}%
\gmlanchor{cap}Capacity planning\gmlend{h2}%
\gmlstart{p}{}%
Each worker thread of Widget Server 4.2 serves about
\gmlstart{m}{}r = 250\gmlend{m} requests per second, so a server with
\gmlstart{m}{}w = 8\gmlend{m} workers handles at most
\gmlanchor{thru}\gmlstart{fml}{id=thru,num=1}T = w \cdot r = 8 \cdot 250 = 2000 \gmlend{fml}requests per second, or 172800000 requests a day.
\gmlend{p}%
\gmlstart{p}{}%
At start-up the 12 cache shards are warmed one after another,
and shard \gmlstart{m}{}k\gmlend{m} takes \gmlstart{m}{}k\gmlend{m} seconds, so the warm-up takes
\gmlanchor{warm}\gmlstart{fml}{id=warm,num=2}\sum_{k=1}^{12} k = {12(12+1)\over 2} = 78\ {\rm s} \gmlend{fml}before the server accepts requests.
\gmlend{p}%
\gmlstart{p}{}%
Plan the offered load \gmlstart{m}{}\lambda\gmlend{m} so that the utilisation
\gmlstart{m}{}\rho\gmlend{m} stays at or below 0.8.
With \gmlstart{m}{}\lambda = 1600\gmlend{m} requests per second and \gmlstart{m}{}T\gmlend{m} from
\gmlstart{fmlref}{refid=thru,resolved=yes,target=fml,num=1}(1)\gmlend{fmlref},
\gmlanchor{util}\gmlstart{fml}{id=util,num=3}\rho = {\lambda \over T} = {1600 \over 2000} = 0.80 \le 0.8 \gmlend{fml}If \gmlstart{m}{}\rho\gmlend{m} in \gmlstart{fmlref}{refid=util,resolved=yes,target=fml,num=3}(3)\gmlend{fmlref} rises above the limit, add workers:
by \gmlstart{fmlref}{refid=thru,resolved=yes,target=fml,num=1}(1)\gmlend{fmlref} each one adds 250 requests per second.
\gmlend{p}%
